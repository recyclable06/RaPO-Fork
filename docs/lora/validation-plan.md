# LoRA 最小验证与实验计划

日期：2026-10-30。状态：首轮代码和微型模型 CPU 检查完成，集群运行待验证。

配套：[设计文档](design.md)、[决策记录](decisions.md)。目标是尽快得到可信的 LoRA + norm/bias 实验结果。以下检查是训练业务的一部分，不是先做完一套测试工程才能开始实验。

## 1. 只保留四项直接关系到实验正确性的检查

| 检查 | 最小做法 | 为什么必须做 |
|---|---|---|
| 参数确实覆盖且参与更新 | 初始化时输出分类数量和未覆盖项，核对共享权重；一次实际更新中检查各类目标参数的梯度路径 | 防止实际只训练语言、漏掉卷积/向量，或参数未交给优化器 |
| 训练与生成使用同一有效模型 | 用少量固定图文输入核对合并前后输出，并检查交给 vLLM 的权重名称与值 | 防止漏合并、重复增量、同步错误却仍生成看似正常的答案 |
| RaPO 任务切换正确 | 在第一次任务切换时检查 Anchor 等于上一任务 Actor、Ref 不变；当前训练不改变二者，CTAN 按原逻辑继承 | 这是 RaPO 方法本身，不是外围安全检查 |
| 保存结果能用于评估 | 沿用现有保存路径，加载一次模型结果，检查 LoRA 和 norm/bias 未丢失 | 避免完整实验结束却没有可用模型；不要求实现断点续训 |

合并数值检查使用固定输出序列和现有 logits/log-prob 接口，考虑 BF16 舍入。若 vLLM 没有方便的同序列评分入口，先核对导出模型数值及实际装载权重，不为验收另造通用评分服务。不能仅凭随机生成相同类别判断权重正确，也不要求不同后端位级一致。

优先把检查放进一次实际运行，必要时加少量局部断言或一次性检查代码。只为不易定位的具体失败补小测试；不预先规定测试数量、覆盖率或跨版本回归矩阵。

当前已有 `tests/test_full_lora.py`，用随机初始化的微型 Qwen2-VL 检查参数化、图文梯度、合并、快照与模型状态重载，另检查未覆盖参数能被指出。运行方式为 `python -m unittest discover -s tests -p test_full_lora.py -v`。这两个 CPU 检查已通过；CUDA FSDP/vLLM、实际 checkpoint 分片重载和首次任务切换尚未通过真实运行验证。

## 2. 最短执行顺序

1. 复用现有入口和已跑通的多卡配置，先选一个 seed，接通初始化、生成和一次参数更新。
2. 跑到第一次任务切换完成上述检查。可以直接利用正式序列的前两个任务；不强制新增“最多两任务”控制器或再跑一遍独立 smoke test。只有迭代耗时确实阻碍排错时，才增加必要的步数限制。
3. 正确后继续完成一个 10-task seed，并用其中一次保存产物检查加载。无需为每个阶段另写报告或重复初始化。
4. 根据准确率、遗忘和资源收益决定是否补其余 seeds、20-task 或调参。出现问题就定位该问题，不自动扩大测试范围。

前两个任务的检查不能替代完整序列结果，但可以与该次完整运行共用。任务中断恢复、自动回滚、故障注入和恢复演练不在首轮工作内。

## 3. 有意义的对照

使用同一原始模型版本、数据划分、类别顺序、提示词、图像处理、rollout 设置、全局 batch、epochs、RaPO 奖励和 CTAN 设置。LoRA 的 rank/alpha/学习率写入现有配置；必要改动如实记录。

第一轮不同时引入更大模型、量化或并行方式改造。调参不反复利用最终测试结果后再冒充独立评估；一个 seed 只形成初步结论。

已有结果足以提供的主要比较项：最终 `last_acc`、`forgetting_rate`、每任务准确率矩阵，以及完成时间。任务矩阵可同时反映新任务是否学会、旧任务是否遗忘，无需另造指标系统。`average_acc` 不与最终准确率混用。

资源收益先利用现有日志和系统工具观察。若要报告具体节省比例，再针对缺失项测量；不要求首轮实现每阶段采样、完整 RAM 归因或性能剖析。

LoRA GRPO 等额外对照，只在后续确实要研究 RaPO 的独立贡献时再设计，不是本轮实现的前置任务。

## 4. 最少记录

沿用现有启动命令/配置快照、训练日志和任务指标。在已有日志中一次性记录参数分类数量、遗漏项及实际改动的依赖版本，实验结束补一段结果解释即可。

不另建逐参数审计报告、每阶段验收包、环境全量锁定流程、持续资源采样文件或进度管理文档。现有材料能说明的事实不重复记录；一次性排错产生且之后用不上的文件在收尾清理。
