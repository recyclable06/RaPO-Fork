# LoRA 改造决策记录

日期：2026-10-30。配套：[设计文档](design.md)、[验证与实验计划](validation-plan.md)。

“已确认”表示用户明确的目标或选择；“当前设计”记录实现取舍。首轮代码及微型模型 CPU 检查已完成，CUDA 分布式与真实训练尚未验证，详见[设计文档](design.md#8-当前用法与验证边界)。技术方案遇到证据后可以调整，不把每一项都变成新的审批流程。

## 已确认

| 决策 | 原因与边界 |
|---|---|
| 覆盖原来全部可训练参数，不限语言或线性层 | 用户明确要求；不得把 `all-linear` 当作完整覆盖 |
| 归一化、偏置等向量直接训练 | 用户明确选择；方案准确命名为 LoRA + norm/bias |
| 保持当前类增量学习方式 | 同一套适配参数顺序学习各任务；不新增每任务独立 adapter 和路由 |
| 没有可复用的已验证实现，可评估独立新环境 | 用户已确认；允许评估不等于必须升级整个框架 |
| 当前先形成实现前文档 | 方案仍待实现，不把文档中的计划写成已验证事实 |
| 精力集中在实验业务 | 优先删除不必要步骤；不建设调度、监控、自动重试或实验控制系统 |

## 当前设计及取舍

### D1：使用一份有效权重导出逻辑

Actor 使用低秩参数和直接训练向量；vLLM、Anchor 使用导出的普通模型权重。

原因：同时解决视觉/连接更新、向量更新以及上一任务模型一致性。避免把更新拆成多个同步通道，也避免每轮写磁盘、重启生成引擎。

代价：仍需同步完整有效模型，并产生合并临时内存。需要实际测量，不承诺全流程资源按适配参数比例下降。

### D2：Ref 独立冻结，Anchor 在任务边界更新

原因：直接训练向量后，关闭 Actor 的 LoRA 不再得到原始 Ref；Actor 与普通 Anchor 参数结构也不一致，不能按参数迭代顺序复制。

代价：保留参考模型副本。先沿用全参数流程的清晰语义，不提前优化为共享底座、多 adapter 切换。

### D3：保留共享权重关系

输入 embedding 与 LM head 若在原模型中共享，同一有效权重应继续服务两处。不能分别训练两份独立增量，否则同时改变了模型结构。

首轮使用 PEFT 处理 embedding，一个小型共享输出头直接读取同一份 A/B。没有采用将转置视图重新注册为第二份 Parameter 的方式，以免 FSDP/优化器将其当作独立参数。共享因子和输出头留在根 FSDP 单元中；普通 Transformer blocks 继续分片。

### D4：只调整必要依赖，不默认升级生成框架

新版 vLLM 已支持部分多模态 LoRA，但独立 adapter 路径不等于全部参数更新支持。先比较真实总改动量，优先保留当前普通模型生成路径。新环境用于隔离和验证，不作为新的部署工程。

### D5：复用保存路径，续训能力不作为首轮目标

原因：本轮需要可用模型结果，不需要新保存格式或恢复系统。沿用现有保存路径，仅修复新参数漏存、结果不能加载等直接问题；完成一次模型重载即可。

任务边界续训、中途恢复、自动回滚、恢复演练都不作为首轮要求；以后有具体需求再处理。正常连续训练中的 Anchor 更新和 CTAN 继承仍然必须保留。

### D6：把验证并入一次真实训练链

只保留参数覆盖、有效权重一致、Ref/Anchor 语义和结果可加载这些直接决定实验正确性的检查。复用一次包含任务切换的实际运行，不先搭测试框架，不强制另写验证程序或短跑驱动器。

启动时报告参数分类数量和遗漏项；保留现有配置、训练日志和任务指标。取消逐参数审计报告、每阶段验收材料和分阶段资源采样的必交要求。分块导出、内存剖析仅在实际瓶颈出现后实施。

## 暂不采用

- 仅语言侧 LoRA：不能满足此次覆盖要求。
- 为归一化和偏置强行设计 A×B：没有相应低秩压缩收益，用户已选择直接训练。
- 每任务新建 adapter、推理时路由：改变当前实验方式。
- 每任务永久合并并重新初始化 LoRA：改变持续更新的参数化及优化器状态。
- 同时引入 QLoRA、更大模型、多套 rank 搜索或框架迁移：扩大变量和实现范围，当前没有必要。
