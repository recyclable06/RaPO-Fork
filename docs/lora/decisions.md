# LoRA 改造决策记录

更新日期：2026-11-01。配套：[设计文档](design.md)、[验证与实验计划](validation-plan.md)。

“已确认”表示用户明确的目标或选择；“当前设计”记录实现取舍。原版全覆盖 LoRA 已在两卡完成四个任务，随后同步合并 OOM；新的分片同步代码和本地 CPU 数值检查已完成，实际多卡运行待验证。详见[设计文档](design.md#8-当前用法与验证边界)。技术方案遇到证据后可以调整，不把每一项都变成新的审批流程。

## 已确认

| 决策 | 原因与边界 |
|---|---|
| 覆盖原来全部可训练参数，不限语言或线性层 | 用户明确要求；不得把 `all-linear` 当作完整覆盖 |
| 归一化、偏置等向量直接训练 | 用户明确选择；方案准确命名为 LoRA + norm/bias |
| 保持当前类增量学习方式 | 同一套适配参数顺序学习各任务；不新增每任务独立 adapter 和路由 |
| 没有可复用的已验证实现，可评估独立新环境 | 用户已确认；允许评估不等于必须升级整个框架 |
| 采用分片方案，先写文档，再实现一版供用户尝试运行 | 分片同步代码及本地检查已完成；后续根据具体结果讨论修改，不自动接管集群实验 |
| 不设显存降幅、速度或 RAM 验收门槛 | 先尝试降低峰值；速度和 RAM 等由后续监听数据分析。此前提出的约 10% 降幅建议不采纳 |
| LoRA 超参数允许独立调整，不强制与全参数更新一致 | 学习率提高约 10 倍是师兄提供的试验建议，不是固定要求；按实际结果选择，记录配置差异即可 |
| 精力集中在实验业务 | 优先删除不必要步骤；不建设调度、监控、自动重试或实验控制系统 |

## 当前设计及取舍

### D1：使用一份有效权重导出逻辑

Actor 使用低秩参数和直接训练向量；vLLM、Anchor 使用导出的普通模型权重。

原因：同时解决视觉/连接更新、向量更新以及上一任务模型一致性。避免把更新拆成多个同步通道，也避免每轮写磁盘、重启生成引擎。

代价：仍需同步整模型量级的数据，并保留独立生成模型。2026-11-01 调整的是导出和加载的驻留方式（D7–D9），不改变有效权重的含义，不承诺全流程资源按适配参数比例下降。

### D2：Ref 独立冻结，Anchor 在任务边界更新

原因：直接训练向量后，关闭 Actor 的 LoRA 不再得到原始 Ref；Actor 与普通 Anchor 参数结构也不一致，不能按参数迭代顺序复制。

代价：保留参考模型副本。先沿用全参数流程的清晰语义，不提前优化为共享底座、多 adapter 切换。

### D3：保留共享权重关系

输入 embedding 与 LM head 若在原模型中共享，同一有效权重应继续服务两处。不能分别训练两份独立增量，否则同时改变了模型结构。

首轮使用 PEFT 处理 embedding，一个小型共享输出头直接读取同一份 A/B。没有采用将转置视图重新注册为第二份 Parameter 的方式，以免 FSDP/优化器将其当作独立参数。共享因子和输出头留在根 FSDP 单元中；普通 Transformer blocks 继续分片。

### D4：只调整必要依赖，不默认升级生成框架

新版 vLLM 已支持部分多模态 LoRA，但独立 adapter 路径不等于全部参数更新支持。先比较真实总改动量，优先保留当前普通模型生成路径。新环境用于隔离和验证，不作为新的部署工程。

### D5：本次不扩展保存与恢复工作

本次仅改变同步临时权重，不改变参数结构和 checkpoint 格式，因此沿用保存路径，不把模型重载、模型导出、断点恢复或回滚演练列为此次交付要求。之后实际使用保存结果或发现相关错误时，再处理对应问题。正常训练中的 Anchor 更新属于本次业务，不能因暂不做恢复而省略。

### D6：把验证并入一次真实训练链

本次聚焦分块合并数值、vLLM 实际装载和 Anchor 写回。优先复用已有小测试或局部数值比较，并由用户的一次实际运行覆盖重新同步与任务切换；不新建测试框架或独立短跑驱动器。

参数注入、优化器、Ref 和 checkpoint 未改时，不重复组织全套梯度、快照隔离或保存重载检查。已有启动摘要和训练日志继续使用，只在定位具体问题缺少信息时补少量输出。完整 10-task、更多 seed 与性能比较不是本次代码交付前置要求。

### D7：CPU 暂存分片，按矩阵聚合并合并

选择：在 vLLM 休眠时用公共状态接口取得 Actor 的 CPU 分片快照；唤醒后，按固定顺序聚合当前矩阵及 A/B，分块计算 FP32 增量，形成 BF16 有效矩阵，加载后释放。

原因：原 `full_state_dict=True` 加完整结果字典的路径已在 task5 发生合并 OOM。分片方案复用作者现有接口，省掉手工管理 FSDP 展开/恢复、flat parameter 偏移和自定义通信协议。

代价：CPU 往返与聚合可能增加同步耗时；分片读取内部仍会展开 FSDP 单元。RAM、耗时和真实峰值由用户运行后的监听数据判断，不预设资源预算门槛。

### D8：保留 vLLM 普通权重加载，分块只用于合并计算

选择：每次向现有 loader 提交一个完整矩阵，沿用名称映射与打包权重处理；不提交同名权重的零散行。分布式聚合由外层固定循环控制，不依赖 loader 是否消费某一项。

原因：完整矩阵满足现有加载器形状要求；不必为进一步省掉单个 BF16 矩阵而修改 vLLM 内部 loader。视觉、卷积、向量和共享权重仍通过一套有效权重语义同步。

新版原生 adapter 路线本次不实施；若当前路线遇到实证阻塞，再比较总改动量。

### D9：Anchor 收集 CPU 目标分片后，一次写回

选择：复用逐矩阵有效权重生成逻辑，按 Anchor 的目标布局生成 CPU 分片，参数名称齐全后一次 `set_model_state_dict`，使用分片模式和 `strict=True`。不累计整模型 GPU 结果，也不逐矩阵对整个 Anchor 做不严格的部分加载。

原因：Actor 带 PEFT、Anchor 为普通 FSDP 模型，不能直接按参数位置复制。公开分片接口是当前较局部的实现选择。

待验证：共享 embedding/head、名称与布局转换、CPU offload，以及写回后 Anchor 的实际使用。该组合是本次主要技术不确定性，可在用户多卡尝试时优先观察；不要求额外建设一套预验证流程。

### D10：把实现范围固定在现有同步业务

选择：主要修改有效权重生成、vLLM 同步和 Anchor 更新三处；保留当前单节点、FSDP、TP=1 的实现范围和 checkpoint 流程。此范围不限制学习率等实验超参数的调整。块大小采用内部实现选择，不增加多种同步后端或大批配置项。

实现使用少量普通函数复用合并逻辑，不新增通用后端抽象或参数登记系统。本轮不建设自动重试、监控服务、回滚、恢复演练、测试框架、逐层日志、异步流水线或通用多节点支持。

名称、设备、形状等常规局部适配直接完成。只有需要深入修改 FSDP 私有结构、重写 vLLM loader 或迁移框架等明显扩大范围的改造时，才根据具体错误与数据重新讨论路线。

## 暂不采用

- 仅语言侧 LoRA：不能满足此次覆盖要求。
- 为归一化和偏置强行设计 A×B：没有相应低秩压缩收益，用户已选择直接训练。
- 每任务新建 adapter、推理时路由：改变当前实验方式。
- 每任务永久合并并重新初始化 LoRA：改变持续更新的参数化及优化器状态。
- 自动化参数搜索、QLoRA、更大模型或框架迁移：不属于本次同步实现；用户通过现有配置尝试不同 rank 或学习率不受此限制。

## 当前实现与运行待确认项

本次保留已运行的依赖与 FSDP 包装；实验超参数按试验需要选择，不锁定为全参数更新或上一轮 LoRA 的取值。内部合并块为 1024 行，名称固定排序，共享 head 随 embedding 一起提供；聚合由外层循环驱动，不交给 loader 决定。用户负责集群尝试运行，之后分析学习效果、峰值、耗时、RAM 和具体错误，再讨论必要修改。能保存在现有配置/日志里的信息不另写一份报告，也不要求每一步更新全部文档。
